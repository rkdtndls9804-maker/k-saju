# K-Fortune MVP 기준선

> 이 문서는 구현 단계에서 충돌하는 기획 선택을 정리하는 실행 기준선이다.
> 제품 방향은 `global_ai_saju_service_plan.md`, UI 방향은
> `global_ai_saju_uiux_design_plan.md`, 계산과 해석의 안전 원칙은
> `engineering/` 및 `saju/` 문서를 따른다.

## 1. 검증 목표

해외 사용자가 Four Pillars를 새로운 자기 이해 콘텐츠로 받아들이고,
자신의 Core Element 결과를 공유하고 싶어 하는지 검증한다.

핵심 지표는 다음과 같다.

- 출생 정보 입력 완료율
- 계산 성공 후 결과 확인율
- 결과 공유 시도율
- AI 해석 섹션 열람률

## 2. MVP 포함 범위

- 영어 우선 랜딩 및 모바일 우선 온보딩
- 양력 생년월일, 출생 시간, 출생지 입력
- 출생 시간 미상 처리
- Four Pillars, Day Master, Five Elements 계산 및 표시
- Core Element Reveal
- Personality, Love, Career AI 해석
- 현재 연도 Year Ahead
- 개인정보를 제외한 9:16 공유 카드
- 입력 오류, 계산 실패, AI 해석 실패의 복구 가능한 상태

## 3. MVP 제외 범위

- 계정, 로그인, DB 저장
- 음력 및 윤달 입력
- 정밀 진태양시 보정
- 결제 및 구독
- 궁합, 친구, Daily/Monthly Fortune, 대운
- AI 대화 메모리 및 푸시 알림
- 검증된 출생 정보 DB가 필요한 K-pop/셀럽 매칭

## 4. 확정된 제품 결정

- 서비스 언어는 영어를 우선한다.
- 비회원 출생 정보는 영구 저장하지 않는다.
- 출생 시간 미상은 허용하며 시주를 비우고 한계를 명시한다.
- Year Ahead는 연도를 하드코딩하지 않고 서버의 현재 연도를 기본값으로 한다.
- 계산 결과는 결정론적 코드가 만들고 LLM은 해석만 담당한다.
- LLM 실패 시에도 계산 결과는 사용자에게 제공한다.
- 미래, 건강, 사고, 임신, 법률 및 재정 결과를 확정적으로 표현하지 않는다.
- 공유 이미지에 생년월일, 출생 시간 및 출생지를 포함하지 않는다.

## 5. 기술 결정

- Next.js App Router, TypeScript strict mode, Tailwind CSS
- 서버 전용 Route Handler에서 계산 및 Gemini 호출
- 런타임 입력과 LLM 출력은 스키마로 검증
- 초기 Gemini 응답은 일괄 방식으로 제공
- 계산, 결과 정규화, 프롬프트 생성, LLM 호출을 독립 모듈로 분리
- 계산 엔진은 검증 표본을 통과한 뒤 최종 채택

## 6. 출시 차단 조건

다음 중 하나라도 충족하지 못하면 공개 출시하지 않는다.

- 알려진 표본과 절기·월주·시주 경계 검증 통과
- API 키와 민감 입력이 클라이언트 번들 또는 로그에 노출되지 않음
- 시간 미상과 AI 장애를 포함한 핵심 흐름이 복구 가능함
- 키보드 탐색, 색상 외 구분, 동작 감소 설정을 지원함
- 주요 모바일 브라우저에서 입력부터 결과 공유까지 완료 가능함
